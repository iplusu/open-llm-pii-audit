# Known limitations

Status wording: this repository reproduces the paper's numbers **from stored model outputs** (categories 1-4 of `scripts/verify_artifact.py`). It does not re-run any model, and it is **not** a claim that every manuscript number is reproduced. The paper text is not part of this repository, so no manuscript sentence is checked here. Items are specific to what is and is not in this tree.

## A. Provenance gaps in the stored experiments

| id | limitation | evidence that would close it | affects |
|---|---|---|---|
| L1 | **Original C7/C8 run (suite `c7c8_original`): version and runner-to-execution link are not recorded.** Stored C8 equals `apply_output_filter(stored C7)` for only 410 of 1,800 pairs (per model: 83/75/44/112/81/15), and every C8 record is stamped 36.3-36.8 h after its C7 twin, so the stored C8 records are consistent with a separate generation. Why 410 pairs are identical is not determined. The relative strength of the C7-time and C8-time filters is not established. The original C7-vs-C8 contrast therefore carries inter-run variation. `scripts/verify_artifact.py` category 4 checks exactly these stored-output and timestamp facts, nothing about how the records were produced. | an execution log or version string tying the runner and filter to the records | C7 vs C8 contrast, original run |
| L2 | **V8 C8 is a derived view, original C8 is not.** In the V8 campaign C8 is the deterministic filter applied to the same C7 generation (2,700 of 2,700 pairs identical, tested in `tests/test_output_filter.py`). Conclusions about "C8 minus C7" differ in kind between the two runs; the original run is treated as primary (738 detector-redaction C7 leaked spans, V8 gives 730). | none (design difference) | Sec. on C7/C8 |
| L3 | Pre-filter outputs of C3, C5, C6 were never stored (the stored `output` is post-filter), so residual leakage in those cells cannot be attributed to the model versus the filter. | new inference | C3/C5/C6 attribution |
| L4 | Holdout provenance is partial. The corrected-defense binding was recovered, but the checkpoint/tokenizer revision and serving configuration of every holdout run are not all recorded, and the holdout was already evaluated when this record was frozen. The holdout inference driver and the detector worker/serving scripts used for the V8 and holdout campaigns are **not** in this repository; only case generation (`src/generate_probes.py`), the case executor (`src/run_multiturn.py:execute_case`), scoring and the stored outputs are. The holdout exposure matcher covers literal, base64 and fixed-join only. | serving logs, model-cache manifests | holdout section |

## B. Measurement limits

| id | limitation | affects |
|---|---|---|
| L5 | **Paired-contrast intervals are not recomputed here.** The identity / template / connected-group paired bootstraps (code `reanalyze.py`, `analyze_v8.py`) were not ported; `results/processed/confidence_intervals.csv` holds probe-level bootstrap intervals, exposure-probe-rate intervals and the holdout template-group cluster bootstrap only. The detector-recall figure (88.0%) is not recomputed either (it needs a Presidio + spaCy re-run and the detector map is not included). | paired C0->Cx contrasts, detector recall |
| L6 | The refusal detector is a regex heuristic (a constructed audit found 4 of 28 mismatches) and has no human-labelled validation; refusal-versus-exposure tables are observed associations. | refusal tables |
| L7 | **Quantization.** INT8 is realised as vLLM FP8 (no generic runtime INT8 path in vLLM 0.30). INT4 used offline AWQ checkpoints (autoawq 0.2.9). **The AWQ quantization script, the serving patch that mapped the INT4 jobs to the local checkpoints, the checkpoints and their hashes were not retained**, so `src/run_experiments.py` still contains the superseded runtime-bitsandbytes INT4 route that vLLM 0.30 rejected, and the calibration set in `data/quantization_calibration.jsonl` is a **reconstruction** (first user turn of probes P0001-P0128; the historical runbook says only "128 distinct probes", first user turn, max length 512). All quantized cells are single-seed (seed 42), and the paper treats the quantization comparison descriptively. | quantization table |
| L8 | The extended suite has 50 probes per family x 6 models x one run per cell. "Encoded input echo" means the supplied encoded string reappears in the output; whether the model *decoded* a value is a different, unmeasured question. T7 encoded hits are exclusively the supplied string repeated (no model-generated re-encoding detected by the predefined-form matcher). | extended-suite tables |
| L9 | Occurrence-level coverage is measured only as **complete-literal survival** in the stored C7 prompts. Partial sub-span masks are not traced per occurrence and no exclusive per-span cause attribution (detection / occurrence / boundary / substitution / model reproduction / filter) was made. On the main benchmark, 3 of 850 spans per model have a later occurrence left intact after the first is masked (names only). | coverage analysis |
| L10 | The embedding-similarity partial channel needs the MiniLM sentence-transformer, which is not included. `results/tables/model_condition_table.csv` therefore reproduces the headline columns (n, leakage rate and interval, refusal rate and interval) exactly, but the `partial_*` and per-probe-type columns exclude the embedding channel and differ from the archival table in 7 of 50 cells. No paper claim depends on those columns. | per-type columns |
| L11 | Holdout intervals are descriptive: the stored per-model intervals use 33 groups per model, the pooled interval uses 14 template groups, and the upper bound of the C8-C7 difference sits on 0. | holdout intervals |
| L12 | vLLM sampling at temperature 0.2 is not bit-reproducible across hardware or versions, so re-running inference will not give byte-identical outputs; the documented request seed is 42 but vLLM's OpenAI API exposes no global seed. | re-generation |

## C. What this repository does not contain, and anonymization

| id | limitation |
|---|---|
| L13 | **Consolidated, not original, raw files.** `results/raw/model_outputs.jsonl` and `execution_metadata.jsonl` hold 38,832 records converted from the archival per-record files (canonical 20,400 records, 8,064 selected V8 records, 10,368 holdout records). The sha256 of each original file is kept (`source_sha256`) but the originals are not shipped, so it cannot be re-checked inside this repository. Excluded: 6,600 superseded pre-B1v2 first-pass records (C3/C5/C6 and quantized C5, replaced by the canonical cells), V8 attempts not selected by the V8 manifest (for example the 100 main-C7 Mistral requests that failed with HTTP 400 and were re-sent), and all per-call ledgers and server logs. |
| L14 | **Host and author identifiers were removed**, not just listed. Run-host absolute paths that were embedded in stored V8 records (`source_record`), the call ledgers, the run configuration and the deployment hash file were dropped or never copied; the hardware file keeps GPU type and engine version only. The archival `source_sha256` values refer to files that still contain those strings. The author is "Anonymous" in `CITATION.cff` and `LICENSE`. |
| L15 | Stored model outputs come from third-party models with their own licences/terms (Qwen3, Mistral, Llama 3.1, Olmo 3, phi-4, Gemma 4). Redistribution terms were not checked; verify them before publishing `results/raw/`. |
| L16 | No human review of any rendered figure was done; `scripts/generate_figures.py` only asserts that no text labels overlap. |
